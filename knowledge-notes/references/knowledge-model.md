# 知识模型与治理矩阵

本文件只在需要判断笔记角色、关系、差异或整库治理时读取。它是决策参考，不是要求项目迁移到固定目录或固定 frontmatter。

## 笔记角色

| 角色 | 主要回答 | 常见连接 |
| --- | --- | --- |
| 索引/地图 | 这个主题有哪些节点，如何继续阅读 | 上位主题、子主题、入口 |
| 概念 | 它是什么，解决什么认知问题 | 上位概念、相近概念、示例 |
| 方法/策略 | 如何做，何时使用 | 前置条件、方案、验证 |
| 架构/方案 | 组件如何协作，为什么这样设计 | 约束、数据流、决策、部署 |
| 示例/案例 | 这个概念如何落地 | 来源概念、方法、结果 |
| 决策记录 | 做了什么选择，舍弃了什么 | 背景、替代方案、后续影响 |
| 事实/参考 | 哪些信息可直接引用 | 来源、结论、适用范围 |

如果一篇笔记同时承担多个角色，优先保留一个主角色，并通过链接连接其他角色；不要为了分类拆出空洞文件。

## 关系选择矩阵

| 关系 | 何时建立 | 链接上下文应该说明 | 是否通常补反向入口 |
| --- | --- | --- | --- |
| 上位/下位 | 一个主题包含另一个主题的范围 | “属于/展开/组成” | 是，至少在索引或地图中 |
| 前置/后续 | 阅读或实施存在认知/流程依赖 | “先读/接下来” | 是，避免单向学习路径 |
| 相近/对比 | 容易混淆或共同解决相邻问题 | “相似处/关键差异” | 是，双方都应能找到对比对象 |
| 对立/取舍 | 目标或约束导致不同方向 | “取舍/冲突/替代” | 是，在决策或比较段落中 |
| 方法/示例 | 示例具体说明方法或概念 | “示例/实现/案例” | 视项目导航习惯决定 |
| 原因/结果 | 一篇解释另一篇的因果影响 | “导致/缓解/影响” | 视阅读路径决定 |
| 替代/场景 | 两个方案可替换但适用条件不同 | “何时选择” | 是，尤其是方案笔记 |

只在链接文字或附近句子中能说清关系时建立链接。只有关键词相同、没有可解释阅读价值时不互链。

## 故事线检查

先写一个句子回答“这篇笔记要让读者理解或决定什么”，再选择结构：

- 概念：问题/背景 → 定义 → 机制 → 例子 → 边界 → 相近概念。
- 方法：目标 → 前提 → 步骤 → 验证 → 失败处理 → 适用边界。
- 架构：背景约束 → 组件职责 → 交互/数据流 → 关键决策 → 故障与扩展。
- 决策：现状 → 选项 → 评价维度 → 决策 → 代价 → 后续影响。
- 索引：主题范围 → 阅读入口 → 子主题 → 推荐路径 → 相关主题。

写完后检查：每段是否回答前一段产生的问题；示例是否证明机制而非装饰；限制是否改变选择；结尾是否告诉读者下一步。

## 相近主题差异矩阵

比较两个主题时，只保留真正影响选择的维度：

| 维度 | 必须回答的问题 |
| --- | --- |
| 目标问题 | 各自解决什么问题，是否只是同义改写？ |
| 抽象层级 | 是原则、机制、工具、实现还是案例？ |
| 前提 | 需要什么数据、环境、权限、时序或团队能力？ |
| 适用场景 | 什么时候优先选择哪一个？ |
| 代价 | 性能、复杂度、维护、迁移或认知成本是什么？ |
| 限制 | 什么情况下会失效或产生副作用？ |
| 组合关系 | 能否同时使用，还是互相替代？ |

至少形成一个选择句：`如果目标是 A 且前提是 B，选择 C；如果约束变为 D，选择 E，因为 F。`

## 治理检查清单

按风险从低到高处理：

1. 修复可推断的相对路径、标题锚点和索引入口。
2. 为孤立笔记找到已有入口或建立最小导航；不能推断归属时只报告。
3. 统一明显的术语和别名，同时保留搜索所需的旧称说明。
4. 发现重叠时先写清边界；只有核心内容和用途都相同才考虑合并。
5. 合并或拆分前保留有效事实、引用和来源；不确定时不删除。
6. 检查新增笔记、索引、相邻笔记和图表是否形成可回溯路径。
