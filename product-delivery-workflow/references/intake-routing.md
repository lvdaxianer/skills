# 入口路由协议

## 目的

入口路由器先判断任务类型、行为风险和范围，再选择足够但不过度的交付档位。路由结果必须可解释、可覆盖、可恢复。

## 输入和输出

路由器读取：

- 用户原始输入；
- 当前项目上下文；
- 已发布的公共和项目 Guardrail；
- 是否涉及代码、测试、配置、数据、外部 API 或部署。

输出至少包含：

```yaml
profile: quick-action | content | bugfix | feature | high-risk
reason_codes: []
confidence: high | medium | low
scope_summary: ...
required_artifacts: []
blocked_reasons: []
override: null
```

## 档位判断

### `quick-action`

仅适用于不改变系统行为的局部文字、格式或说明调整。必须生成最小任务记录和变更验证，不得把它误判为产品功能。

### `content`

适用于文章、README、接口说明、操作手册和产品文档。必须明确目标读者、内容范围、事实来源和审阅检查；不要求完整产品 PRD。

### `bugfix`

适用于复现步骤稳定、期望行为明确、影响边界可控的 Bug。必须生成 Bug Record、回归验证和证据计划。

### `feature`

出现新用户流程、业务规则、API、数据模型、跨模块状态或需要产品取舍时使用。必须进入 PRD 三 Worker 门禁。

### `high-risk`

出现权限、敏感数据、支付、不可逆数据变更、数据库迁移、跨系统集成、生产发布或高额资源消耗时使用。必须进入完整 PRD 和额外风险门禁。

## 自动升级规则

- `quick-action` 如果改变行为，升级为 `content`、`bugfix` 或 `feature`。
- `bugfix` 如果复现不稳定、预期不清、跨多个模块或涉及高风险边界，升级为 `feature` 或 `high-risk`。
- 任意档位只要包含生产部署，都追加部署决策状态，不得自动执行真实部署。
- 低置信度但不高风险时，可以采用默认值继续，同时记录假设；高风险低置信度必须阻塞。

## 人工覆盖

控制台可以修改档位，但必须写入版本化覆盖记录：原档位、目标档位、操作者、时间、原因和影响的产物。覆盖后按新档位重新生成未冻结的产物；已冻结 PRD 不得静默改写。
