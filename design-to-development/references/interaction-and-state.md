# 设计图到交互状态参考

设计图通常只展示理想成功状态。实现前必须把可见设计转换成任务、状态和恢复路径；具体交互红线以 `frontend-interaction-guidelines` 为准。

## 设计输入解析

从文字或图片提取：

- 页面、路由和页面层级
- 主要内容、元数据、状态标签和操作入口
- 主操作、次操作和破坏性操作
- 表单字段、必填项、默认值、校验提示和提交方式
- 列表分页、筛选、搜索、排序和选择行为
- 弹窗、抽屉、菜单、Tooltip、拖拽和键盘路径
- 桌面、平板、移动端和窄屏下的布局约束

图片无法确认的内容写入“设计假设”，不要默默编造业务规则。

## 页面状态矩阵

每个页面至少检查：

| 状态 | 需要说明的内容 |
| --- | --- |
| 初始/加载 | 页面级还是局部 loading，是否使用 skeleton |
| 成功 | 主内容、操作结果和后续路径 |
| 空数据 | 为什么为空，是否提供下一步操作 |
| 无结果 | 搜索/筛选条件和清除路径 |
| 错误 | 用户可理解的原因、重试和保留输入 |
| 无权限 | 隐藏、禁用或说明原因 |
| 离线/超时 | 是否可重试、是否保留草稿 |
| 长任务 | 进度、取消、后台运行和恢复 |
| 窄屏 | 内容收缩、换行、滚动和操作可达性 |

## 操作状态矩阵

对保存、提交、删除、发布、上传、批量操作和搜索逐项定义：

```text
触发前 → 触发中 → 成功 → 失败 → 重试/撤销/恢复
```

- 触发后立即进入 loading/disabled，防止重复请求。
- 删除和不可逆操作必须先确认；确认文案说明后果。
- 乐观更新必须有回滚或可见恢复路径。
- 搜索、筛选、分页和标签切换不能让过期响应覆盖较新的状态。
- 批量操作说明“当前页”还是“全部结果”，并处理部分成功。

## 组件与状态边界

- 页面组件负责任务路径和布局组合。
- 可复用组件接收最小稳定标识，不接收为了方便而传递的完整实体或大对象图。
- Store 保存跨组件、跨路由需要共享的状态；输入、弹窗和局部请求状态优先留在组件或 Composable。
- 相同产品状态使用相同的文案、位置、颜色、时机和恢复方式。
- 项目已有组件库提供能力时，必须先复用；自定义组件要记录搜索过的组件能力和无法复用的原因。

## 视觉验证边界

视觉核对关注布局层级、间距、颜色、字体、响应式和状态反馈；行为测试关注可操作结果。不要用 snapshot 掩盖交互缺失，也不要把一次性设计稿中的静态内容硬编码成不可复用组件。
