# Proposal

## Why

现有部署标准能够约束 release、镜像、健康检查和回滚，但没有把这些要求包装成零基础实施人员可以直接执行的交付包和部署手册。实施人员仍可能拿到没有版本、没有运行时、缺少环境检测、没有一键重启入口或没有客户确认部署目录的材料，从而在安装前后依赖猜测和手工排障。

本变更把部署交付物标准化为一个有版本、可校验、按部署方式分流的统一包，并要求提供可复制执行的一键部署、运维、诊断和回滚入口及现场部署手册。

## What Changes

- 强制部署包具备不可变的包版本、应用版本、源码提交号、构建时间、支持范围和 SHA-256 校验信息。
- 统一部署包支持本机直接运行、Docker 和已有 Kubernetes 集群三种入口；安装前必须选择部署方式并执行只读环境检测。
- 明确三种部署方式各自需要的运行时、镜像/Manifest、配置、持久化和权限材料；Kubernetes 环境不存在或不可用时立即停止，不自动安装集群或降级到其他模式。
- 要求部署包提供 `deploy.sh`、`service.sh`、`doctor.sh`、`rollback.sh` 和 `uninstall.sh` 等面向实施人员的稳定入口，覆盖一键部署、升级、启动、停止、重启、状态、日志、诊断、回滚和卸载。
- 强制在首次安装、升级和迁移前确认客户部署根目录、配置目录、数据目录、日志目录及备份目录；未确认或目录校验失败时不得写入系统。
- 新增部署包清单、环境检测矩阵和部署手册规范，要求每一步包含目的、操作、正常现象、异常处理和完成标志。
- 增加交付前的包契约校验、敏感文件检查、干净环境验证、失败回滚验证和实施验收清单。

## Capabilities

### New Capabilities

- `deployment-package-delivery`: 定义有版本、可校验、按部署方式包含完整依赖和入口的服务部署包契约。
- `deployment-operator-handbook`: 定义面向零基础实施人员的一键部署、运维、目录确认、验收、升级、回滚、卸载和故障交接手册契约。

### Modified Capabilities

- `service-deployment-standard`: 增加部署方式选择、环境检测、客户目录确认、包版本身份和实施入口门禁，同时保持现有 immutable release、健康、回滚和留存要求。

## Impact

- 主要影响 `service-deploy/SKILL.md`、其 references、scripts 和 evals。
- 不新增服务端 API，不改变现有 release record、Docker persistence 或 Dockerfile 的安全要求，只为其增加面向交付和实施的前置契约。
- 部署包构建方需要提供模式专属材料、包版本和干净环境验证证据；客户现场需要确认目录、权限、端口、依赖和已有 Kubernetes 集群信息。
