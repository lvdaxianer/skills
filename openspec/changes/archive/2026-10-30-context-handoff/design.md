# Design

## Context

本仓库中的 skill 以单个目录内的 `SKILL.md` 作为主要行为契约，并可附带 eval 资源。该变更只增加提示驱动的文本整理能力，不引入脚本、外部服务或运行时依赖。详细行为要求见 `specs/context-handoff-output/spec.md`。

## Goals / Non-Goals

**Goals:**

- 让模型能从当前会话抽取事实、决策、状态和后续行动。
- 用固定字段和单一 Markdown 代码块产出稳定、易复制的交接包。
- 在信息缺失、冲突或疑似敏感时采取保守处理。
- 允许用户指定简洁、完整或字段范围。

**Non-Goals:**

- 不自动连接服务器、读取本地文件或调用外部 API。
- 不保证聊天界面以外的复制按钮行为。
- 不保存跨会话数据，也不替代密码管理器或密钥管理系统。

## Decisions

### 1. 使用单一 Markdown 代码块作为输出边界

选择单一代码块而不是自由散文或 JSON，因为用户的主要动作是复制到新会话；Markdown 标题仍然适合模型继续读取，人也容易检查。skill 正文会要求代码块外不添加解释性文字，避免复制时混入噪声。

备选方案：JSON 更适合程序解析，但对普通会话交接可读性较差；散文更自然，但字段不稳定、容易遗漏关键内容。

### 2. 固定字段 + 事实状态标记

交接模板固定包含“会话目标、项目与仓库、服务器与环境、当前状态、已完成、关键决策、关键文件与命令、待办、未决问题与风险、交接说明”。每个字段允许使用“已确认 / 待确认 / 未提供”标记，防止模型把推测当事实。

### 3. 先抽取再压缩

skill 先在内部按“目标—环境—状态—决策—证据—行动”顺序扫描上下文，再按简洁或完整模式输出。只压缩重复和低价值闲聊，不删除能影响下一步执行的约束、失败结果或用户决定。

### 4. 保守脱敏

遇到密码、Token、私钥、Cookie、认证 URL、完整连接字符串或疑似秘密的高熵值时，输出用途和字段名，但替换值为 `[已脱敏]`。不尝试验证秘密、不建议把秘密粘贴到新会话，并提示通过安全渠道补充。

### 5. 用 eval 用例验证可观察行为

eval 覆盖信息完整、信息缺失和敏感信息三类输入；断言检查固定字段、事实不编造、缺失标记和脱敏结果。由于 skill 的核心产物是模型文本，不建立运行时单元测试框架。

## Risks / Trade-offs

- [长会话信息过多导致输出过长] → 简洁模式默认优先保留目标、当前状态、关键路径和待办；完整模式才展开证据和风险。
- [模型漏识别敏感值] → 提供敏感模式清单、保守脱敏规则和“无法确认时也脱敏”的指令；eval 覆盖常见秘密形态。
- [用户希望复制解释但代码块外没有说明] → 在交接包内部增加“使用说明”字段，而不是破坏单一复制边界。
- [项目文档与新 skill 列表不同步] → 将 README 更新和静态检查纳入同一任务的验收范围。

## Migration Plan

无需迁移或回滚数据。合并后将新目录按仓库 README 的安装方式复制或链接到目标 skills 目录；回滚时删除 `context-handoff/` 及对应 README 条目即可。
