# Spec Delta

## Purpose

让笔记在确有必要时使用可维护的配图和架构图降低理解成本，同时保持视觉资源、可编辑图表、正文叙述和项目文件结构之间的一致性。

## ADDED Requirements

### Requirement: 视觉表达必须服务于理解

Skill MUST 判断视觉表达是否比纯文字更能解释主题关系、流程、层级、场景或空间结构；不满足时 MUST 保持纯文字或文本结构，不得为了装饰生成图片。

#### Scenario: 抽象概念适合配图

- **WHEN** 抽象概念难以通过短文本解释，且概念图能帮助读者建立直觉
- **THEN** Skill MUST 生成或建议一张与主题语义一致的配图，并在笔记中说明其解释作用

#### Scenario: 文字已经足够清晰

- **WHEN** 视觉内容不会增加可验证的信息
- **THEN** Skill MUST 不生成装饰性图片，并继续使用文字、列表或表格表达内容

### Requirement: 架构方案图必须可编辑且可核验

Skill MUST 优先使用 Mermaid 或其他项目已有的文本图格式表达架构方案，并在图中体现组件职责、边界、连接方向、数据流或时序以及关键约束。

#### Scenario: 记录一个架构方案

- **WHEN** 用户要求解释系统架构、模块关系、数据流或部署方案
- **THEN** Skill MUST 产出可编辑的架构图，并让图中组件、连线和正文中的职责与决策保持一致

#### Scenario: 架构图需要图片输出

- **WHEN** 用户明确需要图片格式或文本图无法满足展示要求
- **THEN** Skill MUST 在保留可编辑图源的前提下生成 SVG/PNG 等图片，并说明图片不是唯一事实来源

### Requirement: 生成的图片必须纳入知识库资源关系

Skill MUST 遵循项目已有资源目录和命名约定保存生成的图片，使用可访问的相对路径、描述性替代文本和用途说明将图片接入笔记。

#### Scenario: 生成概念配图

- **WHEN** 图像生成能力可用且用户需要概念配图
- **THEN** Skill MUST 生成与笔记内容一致的图片，将其保存到项目资源目录，并在笔记中引用且提供替代文本

#### Scenario: 图像生成能力不可用

- **WHEN** 当前环境无法生成图片
- **THEN** Skill MUST 保留可执行的配图提示或 Mermaid/文本图替代方案，不得伪造图片已生成

### Requirement: 视觉资源和图文一致性必须可维护

Skill MUST 检查图片路径、图表引用、图源和正文说明是否有效；发现孤立资源、失效引用或图文冲突时，MUST 直接修复可确定问题并报告无法判断的部分。

#### Scenario: 图片引用失效

- **WHEN** 笔记引用的图片文件不存在或相对路径错误
- **THEN** Skill MUST 修复可推断的路径或替换为有效资源，并在变更说明中记录处理结果

#### Scenario: 架构图与正文不一致

- **WHEN** 架构图中的组件、关系或约束与正文描述冲突
- **THEN** Skill MUST 以当前明确的需求和证据为依据同步图文，无法判断时 MUST 标注冲突而不擅自编造架构事实
