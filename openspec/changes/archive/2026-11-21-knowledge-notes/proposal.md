# Proposal

## Why

项目内的 Markdown 笔记目前容易退化为彼此孤立的文章：缺少知识体系定位、故事线、相邻引用和同类差异比较。需要一个可复用的 Skill，把写新笔记、改写已有笔记和维护整套项目知识库统一起来，让笔记持续形成可导航、可扩展的知识网络。

同时，抽象概念和架构方案常常需要视觉表达。笔记 Skill 应能在有价值时生成语义配图，并优先产出可编辑、可核验的架构图，保持图文一致。

## What Changes

- 新增面向项目内 Markdown/文本知识库的 `knowledge-notes` Skill。
- 在写作前扫描项目内容，识别主题、层级、笔记角色、已有索引和链接习惯。
- 支持新写、改写、补链、索引维护、重复/重叠识别、孤立笔记治理和断链修复。
- 强制笔记具备问题驱动的故事线，并根据笔记类型调整结构。
- 对相近主题建立明确的差异维度、选择依据和交叉引用。
- 增加视觉表达模式：判断配图价值、生成语义配图、产出 Mermaid/文本架构图，并维护图片与图表引用。
- 直接修改项目文件，但保留有效信息、不随意删除，并在完成后报告变更和未决歧义。

## Capabilities

### New Capabilities

- `knowledge-note-system`: 管理项目内 Markdown/文本笔记的体系定位、故事线、关系链接、差异对比和知识库治理。
- `knowledge-note-visualization`: 为笔记选择合适的视觉表达，生成配图或可编辑架构图，并保持资源、图表和正文的一致性。

### Modified Capabilities

- 无。

## Impact

- 新增一个 Skill 目录及其 UI 元数据，供 Codex 在笔记写作和知识库维护任务中发现和调用。
- 可能新增 Skill 参考文档，但不引入运行时依赖、公共 API 或业务代码。
- Skill 会读写调用方项目内的 Markdown/文本文件及笔记资源文件；默认遵循已有目录、链接、图表和资源约定。
- 使用 Mermaid/文本图作为架构图首选；在图像生成工具可用且确有价值时生成配图或 SVG/PNG 资源。
