# Design

## Context

本仓库是可发现的 Codex Skill 集合，目标产物是一个新 Skill，而不是运行时服务。调用方会把一组 Markdown/文本文件放在项目内；Skill 需要先观察项目已有目录、命名、链接、索引和资源约定，再进行直接修改。当前没有统一的笔记 schema，也不能假设使用 Obsidian 或特定插件。

视觉能力分为两类：架构方案需要可编辑、可核验的文本图；概念配图在确实能提升理解且图像生成工具可用时才生成。Skill 本身不应把图片生成服务或特定图库设为硬依赖。

## Goals / Non-Goals

**Goals:**

- 以短入口规则路由四种工作模式：新写/改写、知识库治理、关系与差异维护、视觉表达。
- 通过一套可复用的知识模型，让笔记先定位体系，再组织故事线、链接和比较。
- 让直接修改可追踪、可解释，并避免不确定的删除或合并。
- 优先产出 Mermaid/文本架构图；可选地调用图像生成能力并把资源接入 Markdown。
- 用参考文档承载关系类型、写作检查矩阵和视觉/架构图细则，保持 `SKILL.md` 入口简洁。

**Non-Goals:**

- 不规定项目必须采用固定目录、YAML frontmatter、标签系统或 Obsidian 插件。
- 不自动删除笔记、批量重命名文件或在证据不足时合并主题。
- 不把生成的 PNG/SVG 作为架构事实的唯一来源。
- 不实现独立的索引数据库、Markdown 解析服务或图像生成 SDK。
- 不修改本仓库已有 Skill 的行为。

## Decisions

### 1. 使用“项目预检 → 目标模式 → 关系维护 → 变更报告”的统一入口

Skill 入口先要求扫描项目相关文件和局部约定，再根据用户意图进入单篇写作、治理、关系维护或视觉模式。所有模式共享关系维护和收尾报告，避免新笔记写完后留下孤立节点。

替代方案是为新写、治理和配图分别建立多个 Skill；这会重复扫描逻辑，也容易让单篇写作和整库维护使用不同的链接标准，因此不采用。

### 2. 以“笔记角色 + 关系类型”而不是固定目录建模

Skill 将笔记识别为概念、方法、方案、示例、索引、决策记录等角色，并用上位/下位、前置/后续、相近/对立、方法/示例、原因/结果、替代等关系描述节点。参考文档提供关系选择和反向链接判断矩阵，但不要求调用方迁移目录。

替代方案是强制所有笔记套统一模板或目录；这会破坏已有项目的组织方式，且无法覆盖不同笔记类型，因此只保留故事线和差异对比等行为约束。

### 3. 用问题驱动的可变故事线，而不是固定文章模板

默认路径为“背景/问题 → 概念 → 机制 → 证据或示例 → 边界 → 对比 → 应用/下一步”，Skill 根据笔记角色删减或重排。参考文档提供最小检查项，入口只保留路由规则。

替代方案是强制每篇笔记包含相同标题；这会让索引、短定义和架构决策记录产生空洞段落，因此不采用。

### 4. 架构图以 Mermaid/文本图为事实源，图片为派生展示物

遇到架构、数据流、时序或部署主题时，Skill 先写可编辑图源，并要求图中组件职责、边界、连线方向和关键约束能在正文找到对应说明。用户需要图片时，在保留图源的同时生成 SVG/PNG。概念配图仅在图像生成工具可用且能增加理解时生成，并写入相对路径、替代文本和用途。

替代方案是直接生成一张不可编辑的架构图片；它难以审查、更新和对比，且容易把模型臆测当成事实，因此不采用。

### 5. 采用轻量文本扫描，不引入运行时脚本

Skill 指示调用者使用项目内已有工具或基础文件扫描能力定位 Markdown/文本、链接和资源。验证阶段使用 `quick_validate.py`、OpenSpec 严格校验、压力场景和针对性 `rg`/链接检查，不新增脚本或依赖，直到真实使用证明重复扫描逻辑值得自动化。

### 6. 直接修改但保留不确定性

用户已授权直接修改。Skill 对路径可推断、断链、索引入口、术语统一等确定问题直接修复；对合并、删除、边界重划等不确定操作保留有效信息，在最终报告中列出歧义和建议。每次操作报告文件、理由、关系变化、视觉资源变化和未决风险。

## Risks / Trade-offs

- [过度链接] → 只有能够说明关系类型和阅读价值的链接才建立，并在参考文档中加入“不要为了数量互链”的检查项。
- [误合并或误删除] → 默认不删除，合并前保留信息并要求有稳定边界判断；不确定时只报告。
- [图文漂移] → 架构图保留 Mermaid/文本图源，完成后检查组件、连线、约束与正文是否一致。
- [生成图片不可复现或不准确] → 图片只作为解释性资源；架构事实必须在正文和可编辑图源中表达，工具不可用时提供文本替代。
- [扫描范围过大] → 优先读取与目标主题相邻的 Markdown/文本和索引，排除 `.git`、依赖、构建产物及工具缓存，必要时再扩大范围。
- [项目约定不明确] → 复用已存在的目录和链接格式；没有约定时采用最小新增结构并在报告中说明。

## Migration Plan

这是一个新增 Skill，不需要迁移已有运行时数据。实现时创建 Skill 目录、入口文档、必要的参考文档和 UI 元数据；验证通过后以单个 OpenSpec task 提交并合并到集成分支。回滚只需回退该提交或移除新增 Skill 目录，不影响已有 Skill 和项目笔记。

## Open Questions

- 具体项目的图片资源目录和 Mermaid 渲染方式由调用时的项目预检决定，不影响本 Skill 的接口或行为契约。
