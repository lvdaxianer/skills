# Spec Delta

## Purpose

让项目内的 Markdown/文本笔记形成可定位、可阅读、可互相导航的知识体系，而不是彼此孤立的文章集合，并支持持续治理已有内容。

## ADDED Requirements

### Requirement: 笔记写作必须先定位知识体系

Skill MUST 在新增或改写笔记前扫描项目内相关 Markdown/文本文件，识别现有主题、目录、索引、命名、标签和链接习惯，并判断目标笔记的知识角色与相邻节点。

#### Scenario: 在已有主题中新增笔记

- **WHEN** 用户要求在已有知识库中新增一个主题笔记
- **THEN** Skill MUST 先指出该主题对应的上位主题、相邻笔记和知识缺口，再开始写正文

#### Scenario: 项目没有现成索引

- **WHEN** 相关笔记存在但没有明确索引或目录
- **THEN** Skill MUST 根据已有内容建立最小必要的导航关系，不得凭空创建与内容无关的分类体系

### Requirement: 笔记必须形成问题驱动的故事线

Skill MUST 让笔记围绕明确问题推进，并按内容需要组织背景、概念、机制、证据或示例、限制、应用和下一步之间的因果或认知顺序。

#### Scenario: 编写抽象概念笔记

- **WHEN** 用户要求解释一个抽象概念
- **THEN** 笔记 MUST 先说明问题或背景，再解释概念如何工作，并以示例、边界或应用收束

#### Scenario: 编写方案或方法笔记

- **WHEN** 用户要求记录一套方案或方法
- **THEN** 笔记 MUST 说明采用条件、关键决策、实施结果或验证方式，以及不适用的情况

### Requirement: 笔记关系必须表达语义

Skill MUST 使用 Markdown 链接或项目已有链接格式表达上下位、前置/后续、相近/对立、方法/示例、原因/结果或替代方案等关系，并在必要时更新相关索引和反向链接。

#### Scenario: 新笔记连接相邻概念

- **WHEN** 新笔记与已有笔记存在前置、相近或后续关系
- **THEN** 新笔记 MUST 建立带有关系语义的引用，并在不会制造噪声时补充相邻笔记的反向导航

#### Scenario: 避免无意义互链

- **WHEN** 两篇笔记只有宽泛主题相同而没有可解释的内容关系
- **THEN** Skill MUST 不创建仅为增加链接数量的引用，并在变更说明中说明未建立链接的原因

### Requirement: 相近主题必须给出可判断的差异

Skill MUST 对相近或易混淆的主题使用一致的比较维度，至少说明它们解决的问题、适用前提、使用场景、代价或限制中的相关差异，并给出选择依据。

#### Scenario: 新增与已有主题相近的笔记

- **WHEN** 目标笔记与一个或多个已有笔记高度相关
- **THEN** 笔记 MUST 包含差异对比，并链接到相关笔记，明确何时选择各自方案

#### Scenario: 发现重复内容

- **WHEN** 两篇笔记表达同一核心内容且没有稳定的边界
- **THEN** Skill MUST 评估合并或重新划分边界，保留有效信息，并在变更说明中记录处理结果

### Requirement: 知识库维护必须直接修复可确定问题

Skill MUST 扫描并直接修复可确定的孤立笔记、断链、索引不一致、术语不一致和明显重复；对于无法安全判断的合并、删除或重构，MUST 保留信息并报告未决问题。

#### Scenario: 修复断链和孤立笔记

- **WHEN** 扫描发现 Markdown 链接指向不存在文件或笔记没有任何有意义的入口
- **THEN** Skill MUST 修复可推断的路径或新增最小导航入口，并在无法判断时报告风险

#### Scenario: 直接修改后的说明

- **WHEN** Skill 完成一次写作或治理操作
- **THEN** Skill MUST 报告修改文件、修改原因、新增或调整的关系，以及未擅自处理的歧义
