# global-knowledge-catalog Specification

## Purpose

为产品和工程人员提供跨项目的问题目录，统一查询、维护和审计错误、近失误与已沉淀规则，同时保留原始证据和历史版本。

## Requirements

### Requirement: 全局目录必须聚合可管理问题

系统 MUST 跨已注册项目和公共知识根目录提供统一问题列表，并返回问题来源、当前归属、生命周期、严重级别、解决方案和证据引用。

#### Scenario: 查询全局问题

- **WHEN** 操作者打开全局问题页面
- **THEN** 系统 MUST 返回所有可见项目和公共问题，并允许按项目、归属、生命周期和严重级别过滤

#### Scenario: 数据源暂时未同步

- **WHEN** 某个文件事实源尚未投影到查询目录
- **THEN** 系统 MUST 返回已知结果并标记同步状态，不得把未同步状态伪装成完整结果

### Requirement: 全局问题必须支持可审计 CRUD

系统 MUST 支持创建、编辑、恢复、排除和归档问题；每次变更 MUST 保存操作者、原因、时间、版本和操作前后的摘要。

#### Scenario: 编辑问题解决方案

- **WHEN** 操作者提交合法解决方案并提供操作者和原因
- **THEN** 系统 MUST 创建新版本并保留旧版本和审计记录

#### Scenario: 删除问题

- **WHEN** 操作者请求删除问题
- **THEN** 系统 MUST 写入可恢复的排除或墓碑状态，不得物理删除原始错误和证据

### Requirement: 全局目录必须支持项目范围

系统 MUST 为每个问题记录来源项目，并允许操作者查看单个项目、多个项目或全局范围的有效问题。

#### Scenario: 查看单个项目

- **WHEN** 操作者选择项目 A
- **THEN** 系统 MUST 只展示项目 A 的项目问题以及明确继承到项目 A 的公共或 hybrid 规则

#### Scenario: 查看公共问题影响范围

- **WHEN** 操作者打开一条公共规则
- **THEN** 系统 MUST 展示该规则已发布、继承或覆盖的项目集合

### Requirement: 全局目录必须显示同步和冲突状态

系统 MUST 为查询结果提供 `synced`、`pending`、`error`、`conflict` 或 `rebuilding` 状态，并提供触发重建或查看错误详情的入口。

#### Scenario: 投影发生错误

- **WHEN** 文件事实源事件无法写入查询目录
- **THEN** 系统 MUST 保留文件事实，标记投影错误并允许稍后重试或从文件重建
